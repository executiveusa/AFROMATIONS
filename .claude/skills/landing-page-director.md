# Landing Page Director

## State machine
LOCK → INSPECT → EVIDENCE → RESEARCH → CONVERSION → TERRITORIES → DESIGN LOCK → SPEC → BUILD → GAUNTLET → REPAIR → PROOF → RELEASE → LEARN

Do not skip directly to BUILD.

## Laws
- Strategy before styling.
- Inspect before changing.
- One page, one dominant job.
- Product proof beats decoration.
- Mobile is a separate composition.
- Proven mechanics may be studied; visual expression must not be cloned.
- Builders cannot approve themselves.
- Production proof beats code confidence.

## Brownfield baseline
Inspect live production, repository, routes, forms, analytics, SEO, metadata, responsive behavior, assets, copy, conversion paths, accessibility, deployment, and rollback.

Classify existing surfaces: KEEP / IMPROVE / REMOVE / UNKNOWN.

## Evidence ledger
Every meaningful public claim is one of:
VERIFIED / USER PROVIDED / ASSUMPTION / MISSING PROOF / DO NOT CLAIM.

## Two-second test
A new visitor should infer:
1. What is this?
2. Why should I care / who is it for?
3. What should I do next?

## Creative territories
Create three materially different directions:
- Restrained / editorial
- Expressive / cultural studio
- Experimental / living world

Do not average them together.

## Anti-slop
Reject generic centered SaaS heroes, random AI gradients, glowing orbs, default bento grids, endless rounded cards, fake metrics, fake logos, AI-brain imagery, hover-only critical actions, generic Get Started CTAs, compressed-desktop mobile, and motion without meaning.

## Release gates
No P0/P1 issues, no broken public routes, no broken primary CTA, no mobile overflow, no critical accessibility failures, zero unsupported claims, rollback documented, and live production verified.
