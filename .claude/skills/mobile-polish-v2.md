# Mobile Polish v2

Preserve working architecture and verified content. Improve the smallest surface that solves the observed problem.

## Required baseline
Record mode, outcome, target, constraints, content policy, proof requirements, ownership, rollback, and commercial value.

Map every primary path:
SURFACE → COMPONENT → HANDLER → ROUTE/SERVICE → DESTINATION → VERIFIED STATE

Classify: VERIFIED / PARTIAL / BROKEN / DEAD / FAKE / UNSAFE / UNKNOWN.

## Required viewports
320×568, 360×800, 375×812, 390×844, 414×896, 430×932, 768×1024, 1024×768, 1440×900.

## Mobile rules
- Mobile is intentional composition, not compressed desktop.
- Essential hit targets at least 44×44 CSS px.
- No hover-dependent essential controls.
- Inputs normally at least 16px on mobile.
- Preserve supplied photography and image focal points.
- No global overflow clipping used to hide layout defects.
- Keep native scroll native.
- Motion must communicate hierarchy, orientation, state, feedback, or narrative.
- Support reduced motion.

## Production proof
Verify routes, forms, error/success states, external links, console, failed assets, metadata, accessibility, performance, exact deployed revision, and rollback.

A build, screenshot, or READY deployment is not production proof.
